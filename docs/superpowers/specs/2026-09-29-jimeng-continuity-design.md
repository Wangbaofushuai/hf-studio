# 即梦直出「视觉连贯性」设计（Phase 2.1）

> 日期：2026-09-29
> 状态：**已实施并验收**（2026-09-29：`job-mumb6tk7-2t2j3e` 30s/6 段/279 积分——同一主角·同一戏台·镜头语言轮换·顶部钩子；实施中发现并修复锚点下载/失败重试/钩子独立三处问题）
> 范围：修正 jimeng 模式的分镜策略、提示词结构、视觉锚点与成片包装；不改 hyperframes 模式

## 1. 问题归因（与现状代码一一对应）

| 现象（用户/AI 分析） | 根因（现有实现） |
|----------------------|------------------|
| 逐句字面直译：金融圈→科幻 HUD、KPI→金色大字、突然出现相声演员、最后孤零零一只手 | `step2` 分镜用的 `prompts/storyboard.txt` 是 **hyperframes 专用**（techniques 全是 kinetic-typography/svg-path-draw 等 HTML 特效词）；`step4` 的 `buildBeatPrompt()` **直接把 beat.narration 当画面提示词**，模型只能逐句具象化 |
| 没有视觉锚点/固定主体：前 20s 无人，中途才出现人物 | jimeng 模式**没有"视觉设定"环节**；每 beat 独立 t2v，无任何跨片段一致性约束 |
| 分镜逻辑是"概念宣传片/PPT"而非"演出转播" | 分镜提示词没有内容类型概念（表演型 vs 讲解型），也没有镜头语言（主机位/特写/反应/肢体）与连续性要求 |
| 包装缺失：无顶部钩子、无网感字幕卡 | 成片仅底部字幕（可选）；无顶部常驻标题、无 BGM/音效 |

## 2. 方案

### 2.1 jimeng 专用分镜提示词（`prompts/storyboard-jimeng.txt`）

step2 在 jimeng 模式改用专用提示词，核心约束：

1. **内容类型判定**：`performance`（人物/舞台/讲述/吐槽）或 `explainer`（概念/数据/教程），写入 `contentType`
2. **视觉设定（visual bible）**：输出 `visual` 块（主体外观与服装、场景与道具、色调、镜头语言），全片复用
3. **镜头语法**（performance）：`shotType` 从固定集合选择——`establishing`（中景主机位）/ `closeup`（近景特写）/ `over_shoulder`（侧身/过肩）/ `gesture`（肢体或手部动作）/ `insert`（道具/字幕卡插入）；**至少 60% 镜头为主体中景/近景**；每 beat 轮换镜头类型，禁止每句换新场景
4. **画面动作优先于旁白**：新增 `visualAction` 字段（该镜头"画面里发生什么"，如"演员拍桌、身体前倾"），**提示词以它为准，旁白不直接进画面提示词**；禁止把抽象名词（KPI/金融圈/对赌）具象为独立新场景
5. **连续性**：同一主体、同一场景贯穿；禁止出现"新人物/新环境"（除非 contentType=explainer 且为图表类镜头）
6. schema 与 `storyboard.txt` 兼容（新增字段可选），非 jimeng 模式不受影响

### 2.2 视觉锚点：定妆图（anchor image）

- step4 生成视频前，先生成**一张锚点图**（即梦 `node create image`，提示词来自 `visual` 块：主体+服装+场景+风格）
- 之后**所有 beat 用 m2v 引用该锚点图的 nodeId**（`--ref node:<anchorNodeId>`），保证同一人物/场景
- 用户上传素材的 beat 优先用用户素材（保持现有 material→m2v 逻辑）
- 锚点图与状态均落 `jimeng/state.json`（`anchor: { nodeId, clipPath }`），重跑复用、不重复生成
- 成本：一次图片生成（低）

### 2.3 beat 提示词重构（`buildBeatPrompt`）

```
【固定】{主体描述}，{场景描述}，{色调/风格}
【镜头】{shotType 对应机位描述}
【动作】{visualAction}
【禁止】不出现任何文字/字幕/水印；不切换主体与场景；不新增人物
```
- 不再使用 narration 作为画面描述
- 短视频：无法保证锚点图与 m2v 的 100% 一致（模型特性），但主体/服装/场景保持同一来源，远优于每 beat 独立 t2v

### 2.4 成片包装（默认开启，纯本地零成本）

- **顶部常驻钩子标题**：ASS 新增 `TopHook` 样式（顶部居中、半透明底、主题强调色），整片显示（文本取 `brief.title`，超 18 字截断）
- **底部字幕**：沿用现有旁白字幕（不变）
- 笑声罐头/BGM：需要素材，暂不做（后续可接入媒体素材；用户也可自己传 BGM）

### 2.5 质量档位（同批做，成本默认不变）

- 向导 jimeng 模式增加「模型 / 分辨率」选择：
  - `样片版 480p`（默认，省钱）
  - `seedance_2.0_mini 720p` / `seedance_2.0_vip 720p/1080p`（质量优先）
- 默认保持样片版；用户可显式升档（费用更高，报价时可见）

## 3. 验收标准（重跑同一主题）

1. 全片 ≥60% 镜头为同一主体的中景/近景；无"新人物/新环境"跳变
2. 每个 beat 有明确镜头类型轮换（非全部同一机位）
3. 画面不出现模型生成的文字/水印
4. 顶部钩子标题 + 底部字幕清晰可读
5. hyperframes 模式与既有测试零回归

## 4. 实施拆分

| Task | 内容 | 交付 |
|------|------|------|
| 1 | `storyboard-jimeng.txt` + step2 jimeng 分支（解析 contentType/visual/shotType/visualAction，写入 `VISUAL.json`） | 单测 + 提示词 |
| 2 | service `ensureAnchorImage`（node create image → quote → confirm → run → wait → download；state.anchor 持久化/复用） | 单测 |
| 3 | step4：先生成锚点图 → 所有 beat m2v 引用；`buildBeatPrompt` 重构（主体/镜头/动作/禁止） | 单测 |
| 4 | ASS `TopHook` 样式 + step6 注入钩子标题 | 单测 + 视觉验收 |
| 5 | 向导：模型/分辨率选择（jimeng） | build + 手工 |
| 6 | 真实 E2E（同一"相声吐槽金融圈"主题重跑，**消耗积分先确认**） | 成片对比 |

## 5. 成本与风险

- 增量成本：锚点图 1 张（低）+ 每 beat m2v（与 t2v 同价），总价与本次相近
- 风险：单张锚点图的一致性弱于"角色 LoRA/主体（Element）"等高级能力；如仍不满意，下一档可接入即梦「主体(Element)」能力（需更多素材与步骤）
- 既有任务重跑时：state 无 anchor → 自动补生成锚点图；已成功的 beat 仍复用（不重复扣费）


## 6. Phase 2.2（2026-09-29 用户反馈后追加）

1. **直出优先**：目标时长 ≤ 所选模型单次生成上限（如 seedance_2.5 = 30s、2.0 系列 = 15s、pro_fast = 10s）时，
   step2 输出**单个 beat**，step4 生成一条连续长镜头，不做拼接；仅当目标时长超出上限才拆分镜拼接。
   （用户反馈："30s 却由 5s 片段拼成，为什么不直出？"——原实现无条件按 LLM 分镜拆分，不合理。）
2. **原生台词配音**：表演型内容把 beat.narration 作为「台词」写入提示词（人物开口说、口型同步），
   **保留即梦原生音轨**，不再叠加 Edge-TTS（避免双声道打架）；讲解型内容仍用 Edge-TTS 旁白。
3. **字幕**：直出单条时按标点分句 + 按字数比例分配时间；拼接模式沿用每段整句。
4. 相关门：jimeng 模式 narration 始终必填（台词）；直出模式要求恰好 1 个 beat、拼接模式 ≥3 个；
   probe 门不再强制音轨存在（静音片段可接受）。
5. 顶部钩子标题：2026-09-29 用户反馈样式不佳，已从 step6 移除（ASS 能力保留，后续如做再做设计）。

6. **写实红线（2026-09-29 追加）**：定妆图风格决定成片风格；默认锚点模型改为 `seedream_5.0_pro`，
   锚点与 beat 提示词均加入写实摄影约束（photorealistic / 自然皮肤与材质 / 禁止插画-3D-卡通）。
7. **时长策略（2026-09-29 追加，用户反馈）**：jimeng 模式不再要求台词凑目标时长——
   每段时长由台词字数反推（4 字/秒，夹到 [4s, 模型单次上限]；直出用模型上限、拼接封顶 15s），
   目标时长仅作参考；相应移除 jimeng 的"总时长 ±20%"与"台词字数"硬门。
8. **思考深度（2026-09-29 追加）**：向导「思考深度」映射 `JobConfig.quality` → step0/1/2 的
   `thinking` + `reasoningEffort`（fast=disabled / balanced=medium / high=high）。
